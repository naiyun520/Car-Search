## 三、问题与风险

### P0-1：主密钥与历史数据不匹配，支付和供应商查询无法工作

当前密钥对 12 条接口 URL 密文的可解密数量为 `0/12`。同时以下安全配置均无法解密：

- 微信 AppSecret；
- 沙箱 AppKey；
- 正式 AppKey；
- 微信消息 Token；
- 微信消息 EncodingAESKey；
- SMTP 密码。

数据库中的 `payment_enabled` 当前仍为 `1`，但支付所需密钥不可用。实际下单会在生成支付参数前失败；定时支付核对也持续记录密钥解密警告。因此当前环境不能进行真实支付、支付轮询、退款、发货消息或供应商查询。

处理要求：优先从旧 PHP 正式环境恢复原始 `DATA_ENCRYPT_KEY`。AES-GCM 密文无法从数据库反推出原密钥。若原密钥确实遗失，必须逐项重新填写并保存所有接口 URL、微信密钥、消息配置和 SMTP 密码，并评估历史订单输入、结果和服务快照不可恢复的影响。

### P0-2：线上仍是旧系统，安全路由和新协议未生效

线上根域名仍跳转 `/admin/`，线上 bootstrap 仍返回旧协议 `20260815.2`。不能仅上传小程序新包，否则小程序会请求新字段和新协议，而线上后端不匹配。

处理要求：先备份数据库，在预发布环境演练数据库增量升级；部署 Spring Boot JAR 和新的 Nginx 路由；确认 `/` 返回 404、自定义后台路径生效、`/admin-api/**` 正常转发，再发布协议 `20260921.1` 的小程序。

### P0-3：iOS 加价配置尚未完成

目前 12 个服务的 Android/iOS 售价差异数量为 0，道具 ID 差异数量也为 0。代码已经支持双端选择，但业务数据没有完成配置。

处理要求：在微信虚拟支付后台创建、审核并发布对应道具，然后逐项填写 Android/iOS 道具 ID 和价格。`goodsPrice` 必须与对应道具后台价格一致，否则微信会返回 `-15013`。Apple 支付不支持沙箱，iOS 真实支付必须使用正式环境、iOS 15+、微信 8.0.68+，且最低金额为 1 元。

### P0-4：隐私运营必填信息为空

数据库中的 `operator_name` 和 `privacy_contact` 为空。虽然后台保存时已要求填写，但当前导入数据没有完成设置。正式上线前必须填写真实运营主体和个人信息保护联系方式，并核对隐私政策、用户授权、数据保留期限和查询合法用途声明。

### P1-1：未完成真实微信支付闭环测试

单元测试和本地接口测试不能替代微信真实接口。本次无法验证：

- Android 微信支付成功、取消、超时和重复请求；
- iOS Apple 支付与 `order_type=7`；
- 支付成功回调丢失后的 `query_order` 补偿；
- 发货通知、重复通知、签名失败和解密失败；
- Android/iOS 退款和 iOS 退款问询；
- 微信后台道具价格不一致、未发布、审核失败等真实错误。

这些场景应在恢复正式密钥并配置道具后，使用体验版和真实设备逐项验证。

### P1-2：反馈“订单类型”的口径需要确认

当前实现按反馈表的 `type` 筛选，合法值为 `bug/order/complaint/other`。如果需求中的“订单类型”指服务编码、服务分类、Android/iOS订单或订单状态，则需要增加订单关联字段或查询条件。正式交付前应由产品/运营确认该字段含义。

### P1-3：个人头像只有展示，没有新用户资料采集入口

已有 `avatar_url` 时页面可以展示头像，但小程序没有 `chooseAvatar` 或资料编辑入口，新用户默认显示中性头像。性别头像不建议实现，因为微信已不再返回性别；如希望提高个人中心完成度，可增加用户主动选择头像的合规入口。

### P1-4：尚未完成微信开发者工具和真机视觉验收

本次环境缺少微信开发者工具，交互浏览器能力也不可用，因此只完成源码结构、资源、接口和构建产物检查。首页图片裁切、安全区、不同屏幕宽度、输入键盘、长文本、底部 tabBar、iPhone 刘海屏和 Android 真机表现仍需人工验收。

### P2：构建工具链存在弃用警告

uni-app 构建成功，但当前依赖为 alpha 版本，并出现 Dart Sass legacy JS API 弃用提示。正式发布版本应锁定经过真机验证的依赖，不建议在上线前临时升级；后续单独安排依赖升级和回归。

## 四、正式上线判定

当前判定：**不通过，不建议直接正式上线。**

代码功能完成度较高，分类、服务、双端价格、安全路径和新版 UI 已具备部署基础；但 P0-1 至 P0-4 未解决前，真实支付、供应商查询、微信回调和隐私合规均不能得到保证。

满足以下条件后可以重新进行上线验收：

1. 恢复正确主密钥，或完成全部敏感配置的安全重录；后台密钥健康状态必须为正常。
2. 填写真实运营主体、隐私联系方式并完成隐私规则复核。
3. 为每个运行服务配置、发布并核对两端道具与价格。
4. 在预发布数据库执行升级并验证回滚方案，确认历史订单数量及状态不变。
5. 部署 Spring Boot 新版本和 Nginx 配置，验证线上根路径 404、自定义后台路径和协议版本 `20260921.1`。
6. 使用 Android 与 iOS 真机完成支付、查询、发货、退款、重试和异常路径测试。
7. 在微信开发者工具完成页面、网络域名、隐私弹窗、包体积及审核前检查。
