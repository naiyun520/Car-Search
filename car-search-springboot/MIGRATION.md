# 迁移兼容基线

## 不允许改变的业务契约

- API前缀保持 `/api/v1`，客户端协议保持 `20260815.2`。
- 响应保持 `{code,message,data}`，业务失败继续使用对应HTTP状态。
- 现有 `ci_*` 表、订单和密文必须可直接读取，不自动建表或改表。
- 用户Token为随机32字节十六进制字符串，数据库只保存SHA-256，最长有效2小时。
- 下单先按 `user_id + request_key` 幂等恢复，再校验业务输入。
- 订单价格、供应商、支付商品和状态全部以后端数据为准。
- 付款成功必须由微信服务端查询或验签消息确认，不能信任客户端success。
- 供应商只在服务端确认付款后查询，`paid -> querying` 必须原子转换。
- 查询输入、结果、服务快照、session_key和安全设置沿用AES-256-GCM加密。
- 微信消息入口保持 `/wechat/message`，仅接受安全模式AES JSON消息。
- iOS退款问询、退款结果、履约状态和后台微信消息列表保持现有行为。

## 切换原则

Spring Boot 与 PHP 先连接同一数据库做影子验证，但不能同时消费微信回调。完成真实测试订单、退款、履约和邮件回归后，再由 Nginx 一次性切换三个入口：`/api/v1`、`/admin-api`、`/wechat/message`。观察期保留 PHP upstream，以便只回滚流量、不回滚数据库。
